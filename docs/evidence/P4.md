## Verification implementation

`web/src/lib/verification.ts` provides a report-only P4 verification layer over the
accepted P2 model and pinned P1/P3 evidence. It contains:

- a CellData-aware audit that emits one receipt per metadata representation without
  deduplicating duplicate rich-text forms and preserves explicit offline methods;
- HTTP/target classification that distinguishes reachable, redirected, dead-target,
  and inconclusive states while making every network outcome insufficient for award
  closure;
- typed date parsing for exact datetimes, date-only values, Google Sheets serials,
  labeled and unlabeled ranges, open-only values, annual rules, rolling rules,
  month-only and approximate values, explicit unknowns, invalid calendar dates, and
  time zones;
- a fail-closed cycle engine in which invalid, unknown, annual-without-year,
  approximate, month-only, or unconfirmed values cannot become active;
- field freshness policies, direct-official acceptance gates, child/parent/provider/
  document/aggregator authority ordering, field-level evidence receipts, and conflict
  decisions; and
- deterministic manual-review severity receipts. These are fixture/workflow severities,
  not independent code-review findings.

Field authority and directness are derived from runtime-validated source bindings,
not asserted by individual claims. Each source binding produces a schema-valid P2
canonical Source and each field receipt embeds a schema-valid canonical Evidence item.
The evidence receipt hash binds the observed subject/field/value, canonical source,
relationship and subject scope, retrieval time, source update time, and source revision;
it intentionally excludes the caller's claim ID so duplicate observations collide and
fail closed. Every generated report also carries a SHA-256 over its complete
deterministic body.
