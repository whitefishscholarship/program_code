## Model schema version 2.0.0

`web/src/lib/canonicalModel.ts` defines runtime-validated schemas for six distinct
concepts:

1. **Source** — architecture, exact canonical URL or offline authority, access behavior,
   authority, acquisition state, identity-bearing query/fragment policy, parent/child
   source links, evidence, and review state.
2. **Scholarship** — independently named award identity, legacy row identity, source
   links with role/provenance, application groups, one-or-more cycles, field evidence,
   review state, and representations for all current student-facing fields.
3. **Application Group** — shared workflow mode, source and scholarship membership,
   supplement state, evidence, and review state.
4. **Cycle** — award relationship, cycle key/year, open/close facts, time zone,
   precision, status, recurrence, application group, evidence, and review state.
5. **Evidence** — field path, subject, source, retrieval time, source revision, claim,
   content hash, verification result, and reviewer state.
6. **Review Item** — subject, typed unresolved reason, state, evidence links, owner, and
   target stage.

The compatibility binding is separate from these concepts. It retains the exact P1
record and points a `Scholarship` row to an award or a `Portal` row to source records,
preventing portal rows from inflating award counts.

## Stable identifier rules

All identifiers use a type prefix plus lowercase SHA-256 over JSON-encoded, ordered,
versioned identity components:

- source: `src_` + hash of exact sanitized canonical URL, or P1 row identity plus the
  explicit offline method;
- scholarship: `sch_` + hash of the immutable P1 row identity;
- application group: `app_` + hash of the P1 source identity;
- cycle: `cyc_` + hash of scholarship ID and cycle key;
- evidence: `evd_` + hash of subject, field path, and claim;
- review item: `rev_` + hash of subject, reason, and deterministic discriminator; and
- legacy binding: `leg_` + hash of P1 row identity.

URL identity uses P1's sanitized exact URL. Meaningful query values and fragments remain
in the identity; P2 does not rerun or broaden URL normalization. Same URL plus different
award rows yields one shared Source and distinct Scholarship IDs. Duplicate scholarship
names do not collapse because row identity, not name alone, is authoritative.

## Old-to-new field mapping

`web/fixtures/p2/legacy-field-map.json` maps all 15 current student-facing headers. Four
fields retained in P1 map directly: row kind, information references, scholarship name,
and application URL/method. Eleven fields were intentionally excluded from the sanitized
P1 input and remain explicitly unavailable: last updated, deadline, audience, amount,
summary, GPA, school type, renewal, focus, financial-need priority, and gap-year state.

The schema represents each excluded field with explicit raw/typed/unknown states and
field-level evidence relationships. P2 does not interpret absence as `Any`, `No`,
non-renewing, active, or another factual value. Award renewal and cycle recurrence are
separate.
