## Acquisition implementation

`web/src/lib/acquisition.ts` is a read-only architecture acquisition layer over P2
schema version `2.0.0`. It provides:

- conservative architecture classification and an explicit route for every P2 source
  taxonomy;
- selective URL canonicalization that removes only allow-listed tracking parameters,
  preserves all other query parameters, preserves meaningful fragments, and sorts
  identity components deterministically;
- visible-text single-page extraction and multi-award section splitting without a
  hidden content-length truncation;
- directory link enumeration that retains every occurrence (including shared canonical
  URLs with distinct labels) and every rejected malformed/unsupported link;
- pagination discovery for identity-bearing page URLs and opaque cursors;
- versioned text/document section parsing;
- representative public-form and Google Forms-style structure reading that records
  question/control metadata but never response values and never submits;
- a bounded queue with a positive work cap, bounded retry count, classified thrown
  timeout/network errors, denominator-bound cursor, and an immutable hash-linked
  receipt ledger required for resume; and
- fixture-only P2 canonical graphs whose Sources, Scholarships, Application Groups,
  Cycles, Evidence, and Review Items all validate and remain unverified for P4.

## Identity and cursor behavior

The identity tests preserve `page`, `urlkey`, `sys_id`, `filters`, arbitrary
non-tracking parameters, repeated values, and non-empty fragments. They remove only
`utm_*`, `gclid`, `dclid`, `fbclid`, `msclkid`, `mc_cid`, `mc_eid`, and `_ga*` tracking
keys. Tracking-only variants canonicalize together; distinct page/urlkey/fragment cases
remain distinct.

Every cursor is bound to the SHA-256 of the exact ordered work denominator and the
digest of the preceding immutable receipt. Resume requires the complete prior receipt
ledger. Receipt hashes, predecessor links, contiguous processed segments, exact
success/failure partitions, and full failure details are validated before resume. A
cursor alone, changed denominator, malformed or altered receipt, cursor/ledger mismatch,
duplicate work key, zero/negative cap, or zero/negative retry count fails closed.
