## Authenticated recovery and idempotency

Receipts are append-only files authenticated with a runtime HMAC-SHA-256 key and linked
by prior digest. They bind plan digest, testing-sheet revision, run ID, mode, segment,
cursor range, results, review items, and full denominator. Tests prove an unkeyed edit
fails authentication and run/mode/cursor mismatches cannot resume.

The recovery scenario places a review item in the first 250-target prefix, then proves
the partial chain cannot finalize or publish. The authenticated suffix restores the
complete 1,028-target ledger with zero duplicates/loss and retains the prefix review.
A repeated complete apply produces the same logical review ID, one queue item, and an
occurrence count of two. Replaying the same authenticated tip remains at one occurrence.
Run IDs are not part of logical review identity, but authenticated run IDs are retained
as occurrence provenance so retrying one run is idempotent.

Only the exact unmodified runtime result of complete authenticated
`apply_review_queue` finalization can return a publishable local review queue. A
structurally forged complete object, mutated finalization, or out-of-plan target is
rejected. Publication cannot publish accepted state or alter accepted facts.
